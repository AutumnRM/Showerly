## P1 · 历史 + 趋势（Cloudflare Workers + D1）
- [ ] **部署 Workers + D1**：`wrangler deploy`；`wrangler d1 create` + 执行 `backend/schema.sql`；用 `wrangler secret put` 存校方 token（当前可留空）。
- [ ] **Cron 每分钟轮询**：`backend/wrangler.toml` 配 `[triggers]`，每 60s 拉校方接口写 D1；关注自由计划免费额度与单次 Cron CPU 时间。
- [ ] **公开接口**：`GET /api/current`、`/api/history`、`/api/status`（后端 `src/index.js` 已适配数组响应 + header 构造）。
- [ ] **大陆可达性实测**：`*.workers.dev` 在国内可能被墙/慢。若不可达，联系计协服务器/树莓派（见 P4）或调研自定义域（仅当确实免费）。
- [ ] **安卓切到 Workers**：`SettingsRepository` 默认 `endpoint` 换成 Workers 地址，App 不再直连校方，token 不再下发到客户端。

## P2 · 人满判定 + 坏位识别 + 趋势
- [ ] **逐浴位接口**：确认校方是否提供每浴位 `bay_status`；抓到则存 `bay_status`，否则仅存计数。
- [ ] **损坏浴位识别**：用「连续空置样本占比」区分：
  - 高频翻转空位（有人离开、下一位未输码）＝ 有效占用；
  - 持续空置占比高 ＝ 疑似损坏浴位。
- [ ] **爆满阈值**：剔除损坏位后，按可配置占用率阈值判定 `status=full`；阈值做成设置项或 `Settings` 可调。
- [ ] **趋势预测**：移动平均 + 线性回归；对比历史同日/同时段，输出预测曲线。
- [ ] **主屏卡片历史线**：用 `/api/history` 的历史数据画每浴室人数折线，替换当前占位框。

## P3 · 军训预警 + 跨用户推送
- [ ] **定时询问**：Workers 定时下发「军训是否结束？」，收集用户应答。
- [ ] **高人流判定 + 推送**：命中高人流时经聚合推送（优先极光/个推免费档）走厂商通道推送；误报率控制。
- [ ] **自有设备回退**：三星 + 类原生小米无厂商通道，回退 Web Push / PWA 或低频本地通知。
- [ ] **iOS 快捷指令回退**：应用内轮询。
- [ ] **志愿者招募**：后续招志愿者提供各品牌设备，配置厂商通道（华为/小米/OPPO/vivo 等）。
